# Try-Catch 问题修改计划

## 修改原则
1. 统一错误处理模式：`catch (e) { console.error(...); this.$message.error(...) }`
2. 后端添加日志，使用正确 HTTP 状态码，不暴露内部错误
3. 所有异步方法必须有错误处理

## 第二阶段：后端修复（3 个文件）

### 统一修改方案

**当前模式（问题）:**
```js
} catch (err) {
  res.json({ code: 500, message: err.message })
}
```

**修改为:**
```js
} catch (err) {
  console.error('操作描述失败:', err)
  res.status(500).json({ code: 500, message: '服务器内部错误' })
}
```

### 8. backend/routes/maintenance.js（8 处修改）

每个 catch 块添加：
- `console.error` 记录错误
- `res.status(500)` 设置正确 HTTP 状态码
- 通用错误消息替代 `err.message`

### 9. backend/routes/auth.js（7 处修改）

同 maintenance.js 修改方案。

### 10. backend/routes/bimface.js（4 处修改）

- 第 42-50 行、55-74 行、79-119 行外层 catch：同上修改方案
- 第 110-113 行内层 catch（已有日志和降级）：**保持不变**，这是好的模式

## 修改顺序

1. **前端**：先修复 3 个缺失错误处理的文件（DetailView、ListView、UserManage）
2. **前端**：修复 4 个只有日志的文件（Dashboard、Form、BimModel）
3. **前端**：修复 RegisterView 和 BimModelView 细节问题
4. **后端**：统一修改 3 个路由文件的 catch 块

---

## 验证方式

1. 前端验证：
   - 断开网络，访问各页面，确认显示错误提示
   - 检查浏览器控制台有错误日志

2. 后端验证：
   - 停止后端服务，前端操作确认错误提示
   - 检查后端控制台有日志输出
   - 确认错误响应 HTTP 状态码为 500
